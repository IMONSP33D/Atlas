# Decision Log

Format: date, decision, why, what it rules out. Newest at the bottom. Open questions at the end.

## Decisions

**2026-11-01 — Atlas is its own project, separate from Perseus.**
Perseus is the team dashboard; Atlas is Sam's personal execution environment. Different lifecycle, different concerns. Perseus keeps only the API contract. Both eventually bundle into Olympus, which gets no project until both have stable interfaces.

**2026-11-01 — Four runtimes: `ephemeral`, `linux`, `windows`, `cape`.**
`ephemeral` for dependency-free code, VM tiers for anything needing a real OS, `cape` for detonation with a report. The agent chooses via the tool call.

**2026-11-01 — `version` is a catalog alias; response echoes the exact build.**
Agent asks for `win10-22h2`, gets back `10.0.19045.5131`. Reproducible without the agent memorising build strings. Unknown versions are a 400 with the catalog, never a silent fallback. Old builds are replaced on rebuild, not kept; the build string is logged per execution so history is traceable.

**2026-11-01 — Both per-execution and per-task (session) modes.**
`mode: execute` is one-shot; `mode: session` keeps state across calls until closed or idle-reverted. Ephemeral tier is always one-shot.

**2026-11-01 — Network: agent requests, Perseus clamps, Atlas enforces. Default deny.**
Atlas refuses rather than downgrades so the agent knows why `pip install` failed.

**2026-11-01 — Hypervisor: Proxmox VE on bare metal.**
Local host is Windows, but Proxmox is the better control plane (API, fast snapshot rollback, CAPE has a native machinery module). Nested under Hyper-V is ruled out as too slow/unreliable for snapshot timing. The Windows box becomes a client.

**2026-11-01 — Guest transport: virtio-serial, no guest NIC by default.**
Rules out SSH/WinRM/HTTP into the guest. `network: false` means the NIC is absent, not firewalled.

**2026-11-01 — Files go in, never out. Only status/output/screenshots return.**
Guest agent has no "send file" verb. 100 MB cap per call, 25 files.

**2026-11-01 — Screenshots: Windows (and Linux) VMs, guest-capture first, hypervisor screendump fallback.**
Agent is told which source it got.

**2026-11-01 — Limits: 10 min execution timeout, 30 min idle revert (warn at 25), 2 concurrent sessions, never Windows+Linux together, sessions killed on Atlas restart.**

**2026-11-01 — Warm/cold is operator config, shown and flippable on a simple dashboard.**
Not agent-controllable.

**2026-11-01 — Auth: one word-seed API key (5 words, hyphenated), hashed at rest, generated by Atlas.**

**2026-11-01 — Error catalog is large and typed, with a `suggested_action` the agent can act on.**

**2026-11-01 — CAPE is a runtime, always async, owns its own analysis VMs.**
Atlas submits and relays the report; it does not manage CAPE's machines. Dropped files are stripped from the report (files don't come out).

**2026-11-01 — Ephemeral image is polyglot:** Python, Node, PowerShell Core, .NET SDK, Rust, C, C++, C#, Go, Bash, plus common compilers and build tools, pre-baked so `network: false` still works for standard libraries.

## Open questions

1. **"10 minute session limit" interpretation.** Docs assume 10 min = max per-execution timeout, and sessions have *no* hard lifetime, only the 30 min idle rule. If a hard session lifetime is wanted, pick a value and add `SESSION_LIFETIME_EXCEEDED`.
2. **Windows licensing for golden images.** Eval ISOs expire in 90 days and nag; a retail/volume key per template is cleaner. Decide before building the first golden image, because the key is baked in.
3. **Session persistence across Atlas restarts.** Decided no (kill all). Revisit only if restarts become frequent enough to annoy.
4. **Multiple Perseus instances / multiple API keys.** Config supports a list of keys; whether each key gets its own rate limit and session quota is undecided.
5. **Callback vs poll for CAPE.** Both supported in the contract; pick one as the primary path once Perseus's tool layer exists.
6. **Dashboard scope.** "Nothing fancy": live sessions, warm/cold toggles, host RAM/CPU, last 50 executions, kill button. Decide whether it needs auth beyond LAN binding.
7. **Linux VM images.** Which distros/versions go in the catalog first. Ubuntu 24.04 LTS is the assumed default.
8. **GPU passthrough.** Not in scope for v1. If RunPod-style GPU work ever lands in Atlas, that's a separate catalog entry with PCIe passthrough.
9. **Where Atlas runs relative to Perseus.** Same LAN assumed. If they ever split across networks, move to mTLS and a real cert (see architecture §5).
